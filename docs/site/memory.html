Memory

Memory is how an assistant remembers what worked. It records the lessons of past sessions, grows more confident in the ones that keep paying off, and quietly forgets the rest — without any bookkeeping from you.

01 — What it is

A confidence store, not a log

A log keeps everything and weights nothing. Memory does the opposite. It holds a small set of lessons — short statements about what tends to work — and each lesson carries a confidence that rises when the lesson keeps proving useful and falls when it does not.

That is the whole point. The first time the assistant solves a hard problem in your project, the solution is hard-won. Memory captures the lesson so the second time is faster. Sessions later, the lessons that kept helping have floated to the top; the ones that were noise have been dropped. The assistant is measurably better at session N+1 than at session N — and you did nothing to make that happen.

After six months you have a tighter memory, not a bigger one.
02 — What goes in

What gets captured

Capture is automatic. At the end of a session the harness records two kinds of fact:

Insights

What was learned

Observations from the session — a fix that worked, a dead end, a preference you stated.

Outcomes

How it went

Did the task succeed, and how much had to be re-done. A first-try success is a clean signal; lots of retries is friction.

Outcomes are what make confidence honest. A lesson is not trusted because it was written down — it is trusted because the sessions that used it went well.

No labour required

You are never asked to rate, tag, or file anything. Capture, distil, and forget all run on their own. The only command you might reach for is rlat memory add, to write a lesson by hand.

03 — How raw notes become lessons

The three distillation arrows

Raw capture rows are noisy. Distillation lifts them, in three steps, from one-off events into durable principles.

Arrow 1 groups one-off events into patterns. Arrow 2 weighs patterns against their outcomes to form learnings. Arrow 3 lifts learnings that hold across different kinds of work into principles.
04 — How memory decides what to trust

Confidence

Every lesson carries a confidence on a four-step ladder — low → medium → high → verified. A lesson is not declared confident; it earns its rung. Five mechanisms move lessons up the ladder:

  • Outcome corroboration — tasks that succeeded after using the lesson.
  • Corpus verification — the lesson checks out against a knowledge model (rlat memory verify).
  • Implicit corroboration — the lesson surfaced in a session that then went well, even with no explicit credit.
  • User corroboration — you confirmed it directly (rlat memory corroborate).
  • Cross-domain accumulation — a principle held up across several different kinds of work.
Confidence climbs as evidence accumulates. A lesson that stays at the bottom and goes stale is dropped — see the next section.

Confidence is also what orders recall: when several lessons are equally relevant to a query, the more confident one surfaces first. Every recalled lesson shows its confidence, so a low-confidence guess is never mistaken for a verified one.

05 — Staying small

Forgetting

Memory forgets on purpose. A lesson is dropped when it has stayed at low confidence, when its source in the corpus has drifted away, or when it has simply gone stale and unused. Several protections hold back lessons that are new, recently useful, or user-written — so forgetting prunes noise, not signal.

The result: memory stays a sharp, small set of things that keep working, instead of an ever-growing pile.

06 — The whole loop

Capture, distil, calibrate, forget — and recall

Each session is captured, distilled into lessons, calibrated for confidence, and pruned. Recall serves the survivors into the next session — which becomes the next thing captured.

Capture, distil, calibrate, and forget run by themselves — on session-end hooks and a session-end consolidation pass. You do not invoke them.

07 — Using it

The commands you actually touch

Most of memory is autonomous. These are the few rlat memory subcommands a person reaches for directly:

CommandWhat it does
rlat memory add "…"Write a lesson by hand. --polarity prefer|avoid|factual tags how to read it.
rlat memory listSee what is in the store, with confidence and recurrence.
rlat memory recall "…"Query memory directly — what does it know about this?
rlat memory corroborate <id>Confirm a lesson — raises its confidence one rung.
rlat memory verify <corpus.rlat>Check low-confidence lessons against a knowledge model.
rlat memory feedback good|badVote on whether the last recalled memory helped.
rlat memory gcManually drop rows — a filtered escape hatch (--polarity, --min-recurrence, --max-age-days).

rlat memory distil and rlat memory consolidate exist too, but they run on their own at session end — you rarely call them yourself.

08 — One thing worth knowing

Memory is outcome-driven, not verdict-gated

Note

An earlier design asked you to /accept or /reject each thing the assistant learned. That gate is gone. A lesson now earns confidence from how tasks actually turn out, not from an up-front verdict. You can still correct memory after the fact — it is just never required.
