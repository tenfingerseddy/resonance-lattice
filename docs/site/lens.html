Lens

A lens is a portable layer that carries your perspective on a knowledge model — what you trust, what you have learned, how you read the corpus. It travels between knowledge models, and a team can pool theirs.

Status

The lens system is built and is being readied for the next release. This page describes how it works; the public surface lands with that release.

01 — The problem

Search starts from zero every time

A plain search tool has no memory of its own. Every query begins fresh. The hard question you worked out last month gets re-researched from scratch this month. Nothing you learned about which sources are reliable, or how this corpus should be read, is carried forward.

A lens fixes that. It is the part of the system that accumulates — so the second time a hard question comes up, the work already done is right there.

02 — The three layers

Source, insight, lens

rlat keeps knowledge in three layers, and they never blur together.

Source is ground truth and never changes meaning. Insight is earned and always traceable down to source. Lens sits on top — and is the only layer that is yours to carry.
Source

Ground truth

The raw passages from your files. Hash-verified, drift-checked, never rewritten. Everything else traces back here.

Insight

Earned summaries

Compact, cited answers built from past research. Each one carries a confidence and points back at the source it came from.

Lens

Your perspective

What you trust, what you have learned, how you read the corpus — packaged so it travels with you.

03 — Inside a lens

What a lens carries

A lens is a small, portable .lens file. It holds:

  • Trust weights — which sources you lean on, and which you discount.
  • Insight preferences — which earned summaries have served you well.
  • A declared stance (optional) — a short written note on how this lens reads the corpus: its scope, what it trusts, what it excludes.
  • Memory — the accumulated lessons from past sessions (see the Memory page).

Crucially, none of this names a specific corpus. That is what lets a lens move — see Portability.

04 — How knowledge compounds

The compounding loop

An insight is not added because someone approved it. It is added because it is faithful — every claim traces to a cited source — and then it earns trust from how things actually turn out.

A deep-search answer must pass the faithfulness gate to become a provisional insight. From there, real task outcomes raise or retire its confidence. Each pass leaves the corpus a little further ahead.

Because a provisional insight is grounded, it is safe to serve right away — carrying a visible provisional confidence. Insights that keep paying off harden; ones that fail retire out of retrieval. No up-front verdict from you is needed at any step.

05 — The trust contract

Source stays sacred

Lenses and insights sit on top of source — they never replace it. Three rules hold that line, always:

  • Source is always reachable alone. Pass --source-only to any search and you get the raw passages, with no insight and no lens applied — the honest baseline.
  • Every hit is labelled. You always see which layer a result came from — source, insight, or lens-shaped — so an earned summary is never mistaken for ground truth.
  • Drift cascades automatically. When a source file changes, the insights built on it are marked stale and drop out of retrieval until re-verified. --include-stale overrides this when you want to see them anyway.

You can inspect any of this directly: rlat audit reports the trust state of a knowledge model, and rlat trace follows a single insight all the way down to the source it rests on.

06 — Portability

A lens travels

Because a lens names patterns of trust rather than specific files, the same .lens can be applied to a different knowledge model. An engineering lens built up against your own codebase can be pointed at a library's documentation, and your perspective comes along — what you tend to trust, how you read things, the lessons you have banked.

07 — Teams

Composing lenses

Several lenses can be merged into one. rlat lens compose takes a set of individual .lens files — a senior engineer's, a compliance reviewer's, a new hire's — and produces a single team lens.

Individual lenses compose into one team lens, applied to a shared knowledge model. Each member's contribution stays attributable.

A team lens reflects pooled trust without flattening disagreement — where members diverge, the difference is preserved and stays traceable to whose lens it came from.

08 — Using it

The commands

CommandWhat it does
rlat lens create --id … --name … -o my.lensStart a new lens. --scope user|role|team|project; --stance <file> attaches a declared stance.
rlat lens show my.lensInspect a lens — its trust weights, preferences, and stance.
rlat lens compose a.lens b.lens -o team.lensMerge two or more lenses into one.
rlat search corpus.rlat "…" --lens my.lensRun a query through a lens.
rlat search corpus.rlat "…" --source-onlyThe honest baseline — source passages, no insight, no lens.
rlat audit corpus.rlat · rlat trace …Inspect trust state, and trace an insight down to its source.
